# Iwa for Frigate

Iwa is a native, open-source (MIT) client for Frigate NVR on iPhone, iPad, Mac and Apple TV. It has two server pieces: `iwa-agent`, a Rust sidecar that runs next to Frigate, and a Rust relay on Cloudflare Workers that carries free end-to-end encrypted push and the paid remote access, Iwa Connect.

## What we never compromise on

1. **Privacy.** Cameras film people's homes. The relay only ever handles ciphertext. Iwa sends no analytics and uses no third-party SDKs. Logs never contain tokens, URLs with secrets, or camera content.
2. **Performance.** People watch live video on battery and over cellular. Every change keeps within the budgets below.
3. **Every route.** A feature isn't done until it works over LAN, Tailscale, VPN, a public URL and Iwa Connect, including over the loopback proxy that Connect uses.
4. **Every surface.** iPhone, iPad, Mac and Apple TV, plus widgets, the Notification Service Extension, Live Activities and App Intents.

## Words

- **you**: the coding agent reading this file.
- **user**: the person using Iwa.
- **server**: one Frigate instance.
- **route**: one way to reach a server (`lan`, `tailnet`, `vpn`, `public`, `connect`).
- **sidecar**: `iwa-agent`. Never call it "agent" in prose, because that word means you.
- **relay**: the hosted Cloudflare Worker.

## Ways to hurt yourself

1. **Sending a credential before identity is proven.** Never send a token or cookie to a route until its descriptor or pinned certificate matches the saved server. A LAN IP on another network belongs to someone else.
2. **Video through a CDN.** Never move camera video or recordings through Cloudflare Tunnel or proxied hostnames. Connect media goes over WebRTC: peer-to-peer, or TURN when that fails.
3. **Touching real cameras.** Don't point tests, scripts or dev builds at the developer's real Frigate without asking. Use the `testbed/` containers or recorded fixtures. When you may use a real server: GET requests on metadata only (no images, clips, or state changes), and never print or commit raw responses. `scripts/capture-frigate` records into the gitignored `.local/`; `scripts/sanitize-frigate-capture` turns that into `fixtures/frigate/<version>/` and refuses to write if any camera name, plate, ID, host, or IP survives.
4. **Committing secrets.** Never commit APNs keys (`*.p8`), `.env` files, Frigate credentials, pairing links or relay tokens.
5. **Editing generated files.** `apple/Iwa.xcodeproj` is generated by XcodeGen. Change `apple/project.yml`, then run `xcodegen generate`.

## Hit every surface

The most common defect is a change that works on the path you tested and nowhere else. Before calling work done, go through this list and say which entries applied:

- **Platforms:** iOS, iPadOS, macOS, tvOS. A tvOS "not supported" decision is fine, but it has to be a decision.
- **Extensions:** widgets, Notification Service Extension (about 24 MB memory and 30 s of time), Live Activities, App Intents and Controls.
- **Routes:** direct and Connect. Something that streams or downloads must also work through the loopback proxy.
- **Frigate versions:** the current and previous minor release. Gate features on server capabilities, not on the app's own version.
- **Roles:** admin and viewer. Viewers never see controls that would fail.
- **States:** offline, data shown from cache, reconnecting, empty, and 64 cameras.
- **Reverse states:** anything you can turn on, you can turn off and see. Mute needs unmute.
- **Accessibility:** Dynamic Type up to the largest accessibility size, VoiceOver labels, Reduce Motion, Reduce Transparency.

## Layout

- `apple/project.yml`: the Xcode project definition. `apple/Iwa/` holds the app target.
- `apple/Packages/IwaKit`: `FrigateAPI`, `IwaConnection`, and future modules. Library modules are `nonisolated` and never import SwiftUI. The app target uses main-actor default isolation.
- `server/`: Rust workspace. `iwa-protocol` must build for both native and `wasm32`.
- `docs/` is local planning material and is gitignored. Never link to it from committed files.

## Verifying

Before you commit, run `scripts/check-changed`. It runs CI's fast checks for what you touched: swift-format, SwiftLint, the IwaKit tests, the app build for the platforms you touched, Rust format/clippy/tests, and gitleaks when installed. CI still runs everything.

While you iterate, run the narrowest command that proves what you changed, and say exactly what you ran (scheme, destination, filter):

```sh
cd apple/Packages/IwaKit && swift test --filter RouteKindTests
cd apple && xcodegen generate && xcodebuild -project Iwa.xcodeproj -scheme Iwa \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build -quiet
cd server && cargo test -p iwa-protocol
```

Build every platform you touched (iOS Simulator, `generic/platform=macOS`, tvOS Simulator); `scripts/check-changed --all-platforms` does all three. CI runs everything else. `scripts/install-hooks` adds a pre-commit hook with the fastest checks.

UI and launch tests (`IwaUITests`) need macOS Automation Mode. Enable it once with `automationmodetool enable-automationmode-without-authentication` (asks for your password), or leave them to the nightly CI run.

## Tests

- Test behavior that can break: route selection, identity checks, auth, encryption and wire formats, Frigate response decoding, notification rules, migrations, race fixes. Skip what the type system already guarantees, trivial getters, copy text and view wiring.
- Extend before adding. Add a row to an existing parameterized `@Test(arguments:)` when one fits.
- Test at the lowest layer that fails without the fix. Don't repeat a case in Swift and Rust unless it's a shared test vector in `fixtures/`.
- A logic, data, protocol or security bug gets a failing test first, then the fix. A purely visual bug gets before and after screenshots instead of a test.
- **No real time in tests.** Decision logic is a pure state machine fed with events (see `RouteRace`), or takes an injected `Clock`. These are banned in tests, and SwiftLint enforces it: `Task.sleep`, `Thread.sleep`, `Date()`/`.now` deltas, polling loops, `.timeLimit`, and retries. A flaky test gets fixed, never retried.
- Random inputs come from a seeded generator (`SplitMix64` in the test fixtures), so a failing seed reproduces exactly.
- Skipping a test needs its tracking issue in the reason: `.disabled("quarantine: #123 <why>")` in Swift, `#[ignore = "quarantine: #123 <why>"]` in Rust.
- Use Swift Testing (`@Test`, `#expect`, `#require`) for new tests. Use XCTest only for UI automation and performance metrics.

## Budgets

Budget files live in `budgets/` and may only grow when a PR carries the matching label (`size-increase`, `perf-increase`, `wire-increase`); `scripts/check-budget-growth` enforces it in CI. App size ratchets: `scripts/app-size` fails above `budgets/size.json`, and `scripts/app-size --update` resets the limits after an intended increase. Changes to permissions, entitlements, ATS, the privacy manifest, or the framework allowlist in `scripts/check-app-bundle` need the `privacy-reviewed` label.

Targets as the app grows:

| Budget | Limit |
|---|---|
| iOS download size (thinned) | ≤ 30 MB |
| Cold launch to first frame (iPhone 15-class) | < 400 ms |
| First live video frame from cold launch | LAN < 1.5 s · Tailscale < 2.5 s · Connect P2P < 3 s · Connect TURN < 4 s |
| Notification Service Extension memory | < 20 MB |
| Main-thread hang | none > 250 ms |
| 16-camera grid | < 400 MB, no growth over 5 min |
| APNs payload | < 4 KB with the longest names |

A new dependency needs a reason in the PR and its size cost. Prefer Apple frameworks.

## Taste

- Swift: start with the simplest thing. Value types, `some` before `any`, main actor before `async`, and `@concurrent` only after profiling. See the `write-swift` skill.
- Motion: animate only with a purpose. UI transitions take 300 ms or less and use interruptible springs. Every animation has a Reduce Motion alternative. **No continuously looping animations**: a camera grid is already repainting video, so shimmer and pulse effects drain the battery.
- Liquid Glass belongs on controls and navigation, never over video content.
- Default to no comment. Write one only for a constraint, an external quirk, or an invariant the code can't show.
- Log with `Logger` and its privacy annotations. Mark something `.public` only when it's provably not personal.

## Pull requests

- `master` is protected: every change lands through a pull request with green CI (Changes, Hygiene, Apple, Rust), admins included. No force pushes.
- Branch names: `<type>/<topic>`, e.g. `feat/frigate-login`. Squash-merge.
- Use conventional commit titles: `fix(connection): never reuse HTTPS tokens on learned HTTP routes`.
- Budget growth needs its label (`size-increase`, `perf-increase`, `wire-increase`); permission, entitlement, ATS, privacy-manifest, or framework-allowlist changes need `privacy-reviewed`. A maintainer adds labels; don't add them to your own PR.
- UI changes need before and after screenshots for each affected platform. Motion needs a short video.
- One request is one PR.
